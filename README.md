# Дипломная работа — автоматизация тестирования

Проект автоматизации для дипломной работы по профессии «Инженер по тестированию» (Sky.Pro). Автор — Селиванов Георгий.

Итоговый отчёт и вся документация по проекту (тест-план, тест-кейсы, чек-лист, баг-репорты, скриншоты прогонов, презентация, видеозащита): https://georgi1412qa.yonote.ru/share/5222c94a-8b37-4324-822a-e8b78ffc8325

## Тестируемые приложения

- **UI:** книжный интернет-магазин **Читай-город** — https://www.chitai-gorod.ru (гостевой доступ, без входа в аккаунт).
- **API:** **Todo List API** — https://jsonplaceholder.typicode.com/todos (публичный REST-сервис, без авторизации).

Изначально API-часть тест-плана была рассчитана на приватный тестовый сервер (`http://5.101.50.9:8015`), уже вручную проверенный в Postman (17 из 17 тест-кейсов). Сервер перестал отвечать по сети, поэтому API-тесты переведены на публичный сервис с той же моделью Todo-ресурса (GET списка и одной задачи, POST, PATCH, DELETE).

## Ключевые функции, покрытые тестами

1. **Поиск книги** (UI, Читай-город) — поиск по названию и по фамилии автора, отображение результатов. Файл: `tests/ui/test_chitai_gorod_search.py`.
2. **Просмотр карточки товара** (UI, Читай-город) — переход из выдачи в карточку, отображение названия книги. Файл: `tests/ui/test_chitai_gorod_search.py`.
3. **Управление задачами через API** (Todo List) — 5 позитивных проверок CRUD (`tests/api/test_todo_crud.py`) и 3 негативные: несуществующий id, id неверного формата, неподдерживаемый метод (`tests/api/test_todo_negative.py`).

Все функциональные UI-тест-кейсы позитивные, негативные сценарии вынесены в API-тесты (негативных — 3, позитивных — 5). Селекторы и коды ответов подтверждены вручную на живых сайтах перед написанием тестов.

## Стек технологий

## Установка

```bash

pip install -r requirements.txt
playwright install chromium
```

Переменные окружения и авторизация не требуются — оба тестируемых ресурса открыты без входа.

## Запуск тестов

Проект поддерживает три режима запуска через маркеры pytest:

```bash
# все тесты (13 шт.: 8 API + 5 UI)
pytest --alluredir=allure-results

# только UI
pytest -m "ui" --alluredir=allure-results

# только API
pytest -m "api" --alluredir=allure-results

# отчёт Allure
allure generate allure-results --clean -o allure-report
allure open allure-report
```

## Качество кода

```bash
flake8 .
```

Отчёт линтера чистый (0 ошибок, 0 предупреждений; настройки — в `setup.cfg`). Все функции содержат аннотации типов для параметров и возвращаемого значения. Автотесты независимы друг от друга и от порядка запуска: у каждого UI-теста свой контекст браузера. Жёсткие ожидания (`time.sleep()`) не используются — только явные ожидания Playwright (`wait_for_url`, `wait_for_selector`, `wait_for_function`, `expect`).

## Статус проверки

Полный набор из 13 тестов прогнан локально 23.09.2026 в 20:22 (Windows 11, Python 3.12.10): `pytest --alluredir=allure-results` → **13 passed, 0 failed** за 34,7 сек (8 API + 5 UI). Allure-отчёт: 100%. Скриншоты отчёта — в папке [`screenshots/`](./screenshots).

Что исправлено в UI-тестах по ходу прогонов:

- ожидание `networkidle` не наступает на chitai-gorod.ru из-за постоянных фоновых запросов сайта — заменено на явные ожидания нужного адреса и элементов;
- ссылки `a[href*="/product/"]` есть и на главной странице, и в скрытом списке подсказок поиска, поэтому проверки «товары найдены» могли пройти без выполнения поиска. Теперь тесты ждут перехода на `/search` и берут карточки только из блока выдачи `.app-products-list`;
- после поиска выпадающий список подсказок оставался открытым и перехватывал клик по карточке товара. Теперь тест дожидается подсказок, отправляет запрос и закрывает список;
- если вводить запрос до того, как клиентское приложение страницы смонтировалось, ввод терялся. Теперь тест ждёт монтирования приложения.

Postman-коллекция с теми же 8 API-кейсами (5 позитивных + 3 негативных): [`Todo_List_API_JSONPlaceholder.postman_collection.json`](./Todo_List_API_JSONPlaceholder.postman_collection.json). Переменные `base_url` (используется во всех запросах) и `token` (не применяется — сервис без авторизации) вынесены в коллекцию. Во всех запросах есть проверка статус-кода, в позитивном сценарии создания задачи — сохранение id созданного объекта (`pm.collectionVariables.set`).

## Найденные дефекты

- **BR-001** (серьёзность Minor, приоритет Low): контраст текста бейджа скидки (например «-17%») на главной странице chitai-gorod.ru — 4,04:1 при пороге WCAG 2.1 AA 4,5:1 для обычного текста. Белый текст (#FFFFFF) на фоне #E1426C, 12px, начертание 500.
- **BR-002** (серьёзность Major, приоритет Medium): сильные сдвиги макета при загрузке главной страницы — Cumulative Layout Shift 0,7 по данным реальных пользователей Chrome за 28 дней (PageSpeed Insights, компьютеры), при норме ≤ 0,1 и пороге «плохо» > 0,25.
